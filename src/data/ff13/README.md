# FF13 upgrade data

Generated by `scripts/ff13/fetch.py` then `scripts/ff13/build.py`. Do not edit the JSON by hand;
put corrections in `COMPONENT_OVERRIDES` in `build.py` so they survive a rebuild.

Source: guides.gamercorner.net/ffxiii (table CSVs + detail pages), cross-checked against
finalfantasykingdom.net, jegged.com and Geoff Finger's upgrade mechanics FAQ.

## Files

| File | Shape | Contents |
|---|---|---|
| `components.json` | `{ id: Component }` | 141 components |
| `weapons.json` | `{ id: Weapon }` | 144 weapons (48 per tier) |
| `accessories.json` | `{ id: Accessory }` | 119 accessories |
| `shops.json` | `{ shopId: { id, name, stock: [Offer] } }` | Only shops that sell components or weapons |
| `constants.json` | object | Bonus tiers, rank range, batch limit, chip ids |
| `index.js` | | Maps, lists (`ItemMap` merges weapons and accessories) and `OffersByItem` |

## Upgrade rules encoded here

- **Rank (1-11).** Every weapon and component has one. Rank 1 gets the most EXP from components.
  `component.expByRank[weapon.rank - 1]` is the EXP one component gives that weapon at a 1x multiplier.
- **Multiplier.** Each component adds `bonus` (organic: positive, mechanical: negative) to the item's hidden
  bonus total. The total picks the multiplier from `constants.bonusTiers`
  (0 -> 1x, 51 -> 1.25x, 101 -> 1.5x, 201 -> 1.75x, 251 -> 2x, 501 -> 3x). The multiplier applies to a batch
  *before* that batch's own bonus is added.
- **Batch size.** At most `constants.maxComponentsPerBatch` (99) of one component per application.
- **Level cost.** The EXP to *reach* level L (L >= 2) is `expBase + expPerLevel * (L - 2)`.
  Level 1 costs 0. `masterExp` is the total from level 1 to the mastered level (`maxLevel`, shown as a star).
- **Upgrading.** A mastered item plus its `upgradesTo.catalyst` becomes the next item, created at
  `upgradesTo.startLevel`. All EXP carries over, so the remaining EXP for the new item is
  `next.masterExp - current.masterExp`, not `masterExpFromStart`. If the new item is created at the star
  level (Entite Ring -> Goddess's Favor), the carried EXP overshoots and the excess is lost.
- **Weapons and accessories share the upgrade fields**, so one calculator handles both. Accessory chains can
  be longer than three stages.
- **Ultimate weapons (tier 3).** Same in-game name per character but separate entries (`kains-lance-1` ... `-8`),
  displayed as `Kain's Lance (Bladed Lance)`. `originWeapon` is the tier-1 weapon the chain started from.
  Every tier-1 weapon maps to exactly one ultimate weapon (`ultimateId`).

## Weapon

```
id, name, baseName, character, tier (1-3), rank, ability, extraAbility, synthesizes, chapter, description
  name      unique display name; ultimate weapons read "Omega Weapon (Blazefire Saber)"
  baseName  the in-game name (shared by all of a character's ultimate weapons)
startLevel   level you have when you first get it (1 for purchasable items)
anchorLevel  level the formulas below are anchored at (the first level of the source table)
maxLevel
maxStrength, maxMagic        stats at the mastered level | null if the weapon has no such stat
ultimateId                   id of the tier-3 weapon this one ends up as (itself for tier 3)
expBase, expPerLevel, masterExp, masterExpFromStart
strength / magic / sellValue : { atAnchor, perLevel } | null    value at level L = atAnchor + perLevel * (L - anchorLevel)
buyPrice                     first listed price; use shops.json for real offers
kind         "weapon"
upgradesTo   : { item, catalyst, startLevel } | null
upgradedFrom : [{ item, catalyst }]    usually one entry; Twenty-sided Die has six
originWeapon : weapon id | null
dismantle    : [{ id, type: "component" | "weapon", qty }]   what a mastered weapon breaks down into
```

## Accessory

Same fields as a weapon (`kind: "accessory"`, ids, ranks, levels, EXP, `upgradesTo`, `upgradedFrom`, `dismantle`,
`sellValue`, `ultimateId` = last item of the chain) except:

```
ability      template such as "HP: +X"
bonus        { atAnchor, perLevel } | null     the X in the ability; null when the ability has no number
maxBonus     X at the star level | null
```

Upgrade-only accessories are created at `upgradesTo.startLevel` of their source, and `startLevel` reflects that,
but some of their pages still list levels from 1, which is why formulas use `anchorLevel`.

## Component

```
id, name, type ("organic" | "mechanical" | "catalyst"), rank, baseExp, bonus
expByRank   : 11 numbers (index 0 = rank 1) | null for catalysts
buyPrice    : lowest listed shop price | null
sellPrice
premium     : true for chips, dolls, ingots, etc. ("can be sold for a premium")
chapter, description
```

## Offer (`shops.json`)

```
{ itemType: "component" | "weapon", itemId, price, chapter, note }
```

`chapter` is the first chapter the item is stocked. `note` carries conditions such as
"Available after completing Mission 46".

## Known data quirks

- Six Gilgamesh, Inc. weapons cost 20x their level-1 sell value instead of 2x (Organyx, Aldebarans, Sacrificial
  Circle, Malphas, Tigerclaw, Dragoon Lance). This is real; see `GILGAMESH_MARKUP` in `build.py`.
- Tungsten Tube sell price is overridden to 420 (GamerCorner says 480, two other sites say 420).
- Credit Chip and Incentive Chip are listed as `mechanical` components. They are sold for gil
  (500 and 2,500) and are not purchasable.
- Royal Armlet is sold by Sanctum Labs for 200,000 gil, 10x its sell value instead of the usual 2x. Only
  GamerCorner lists it, so it is unverified. The calculator never uses accessory buy prices.
- Consumables and the consumable shops (Unicorn Mart, Eden Pharmaceuticals) are not included.

```
pip install beautifulsoup4 lxml
python3 scripts/ff13/fetch.py     # caches pages to /tmp/ff13-cache (set FF13_CACHE to change)
python3 scripts/ff13/build.py     # rewrites this folder; exits 1 if any validation check fails
```
